# 네 빌드 분리 — 검증 기록

실행일 2026-10-01, Unity 6000.4.0f1. 기준 프로젝트는 `/Users/gimdong-yun/GitHub/Grid-Caster`, 변경 전 HEAD는 `55375be`, 변경 작업은 로컬 `feature/build-identity-pruning` 브랜치다. main 병합·GitHub 게시를 하지 않았다.

결론: 네 빌드의 중복 효과를 실제 판정·후보·설명에서 분리했다. 규칙/후보/UI 회귀와 실제 SampleScene 자동 런으로 검사했다. 재미·이해도·사람 승률·최적 균형을 확정하는 실험은 아니다. [현재 효과](../../GrowthAndRelics.md), [가설·변경 이력](../design/four-build-identities-2026-10-01.md)을 함께 읽는다.

## 환경과 실행 방법

* 원래 프로젝트에 활성 Editor가 없는 것을 확인하고 네이티브 Unity 배치에서 실제 Play를 실행했다. 실행 중이던 HiJackPot Editor는 종료하거나 수정하지 않았다.
* 비동기 Play 검사는 `-quit` 없이 실행한다. UI 클릭 검사는 `-nographics`를 쓰지 않는다.
* URP 환경, Input System, uGUI, 32 PPU/Point 에셋을 유지했다. 씬·Prefab·아트·패키지·적 스탯·웨이브 조합·카메라를 변경하지 않았다.
* 연출만 가속하며 정상 자동 런의 체력/피해/적 AI/턴/무작위 보상은 우회하지 않는다. 규칙 fixture에서만 적 체력·보유 강화·강제 발동 롤을 구성한다.
* 보고서의 `sourceHash`는 검사기가 지정한 런타임 파일과 씬의 해시이며 전체 저장소 해시가 아니다. `policyHash`는 검사기 전체 파일 해시라 assertion/기록 코드 변경에도 달라진다.

## 자동 플레이 반복 진단

두 `turn_limit`은 캐릭터 체력 10, 마지막 비숍 한 마리만 남은 상태에서 플레이어 비숍 활보가 대각선 이동을 반복했다. trace에서 플레이어/비숍의 색이 계속 반대였고, 이동·적 턴은 정상적으로 진행했다. 엔진 정지나 입력 차단으로 처리하지 않는다.

검사기에 별도 `bishopParityEscape` 옵션을 추가했다. 마지막 적이 비숍이고 서로 다른 색일 때 공개 좌표로 색을 바꾸는 기본 한 칸 이동을 가산한다. 숨은 발동·RNG나 미래 예약을 읽지 않고, 게임 판정·몬스터 능력을 바꾸지 않는다. 이 옵션을 켠 결과는 정책이 다르므로 위 고정 정책 승률과 합산하거나 전후 비교로 사용하지 않는다.

별도 정책으로 같은 초기 시드 32런을 실행해 완료했다. [진단 원본](four-build-parity-diagnostic-2026-10-01.json)은 동일 런타임 `sourceHash`이며 더블 1/8, 관통 1/8, 데미지 4/8, 넉백 1/8 클리어, 턴 제한 0건이다. 네 빌드의 전설 없는 클리어 사례는 유지되었다. 정책 변경은 다른 시점의 선택·RNG도 바꾸므로 특정 과거 전장을 똑같이 재생해서 탈출을 증명한 결과는 아니다. 승률 개선으로 해석하지 않고 반복 선택의 진단 자료로만 사용한다.

## 판단

* H1(빌드마다 다른 판단이 재미있다): 판정의 역할 분리는 확인. 사람의 판단 변화·재미는 미검증.
* H2(범용 효과를 덜어도 전설 없이 진행 가능): 네 빌드의 클리어 사례 확인. 처리력·체감 난이도 균형은 아직 가설이며 보상 횟수 축소로 성공시킨 것은 아니다.
* H3(간결한 카드+정확한 상세): 문구·줄바꿈·클릭·비용/레벨 표시는 확인. 이해도는 사람 관찰 필요.

이번 단계에서는 이 이상 봇 승률만 올리려고 범위 피해·주변 봉쇄를 복구하지 않는다. 실제 사람이 네 빌드를 플레이하고 ‘공격 방향/대상을 고른 이유, 줄 세우기, 초과 피해 활용, 충돌 활용, 보상 선택 후 만족/혼란’을 보고 다음 조정을 정한다.

## 재현과 직접 테스트

Unity에서 SampleScene을 열고 Play. 새 GameObject/컴포넌트/태그/레이어/Tilemap 설정이나 Inspector 할당은 필요 없다. A는 공격, S는 기본 이동+이동술, 좌클릭 확정이다. 시작에서 회전 영창·관통 가속·초과 전달·충격 고정을 확인하고 보유 항목을 클릭해 상세를 읽는다. 재조준 중 S/이동은 차단되어야 한다.

에디터 메뉴 `Tools > Playtest > Validate Reward Usability`, `Validate Chess Playtest`, `Validate Run Balance`도 사용할 수 있다. 검사가 전투 상태를 구성하므로 정상 플레이 중 실행하지 말고 씬을 저장한 뒤 별도 실행한다.

배치 예시:

```sh
"/path/to/Unity" -batchmode -projectPath "/path/to/Grid-Caster" \
  -executeMethod RunBalanceValidation.RunBatch \
  -balanceRequest /tmp/four-build-request.json -logFile /tmp/four-build.log
```

요청 JSON:

```json
{
  "label": "four-build-reproduction",
  "outputPath": "/tmp/four-build-result.json",
  "firstSeed": 4100,
  "seedsPerTrait": 8,
  "allowRelics": true,
  "avoidLegendary": true,
  "validateMechanics": true,
  "recordLastActions": true,
  "bishopParityEscape": false
}
```

별도 반복 진단은 마지막 옵션만 true로 바꾼다. UI 배치는 `-executeMethod ProgressionUsabilityValidation.RunBatch -fourBuildValidation`을 사용하면 현재 UI 원본 파일을 갱신한다.
