# 준비한 특성 공격: 구현·검증

> 2026-10-02 후속 변경: 특수 공격 단축키는 Shift+A에서 **F**로 바뀌었다. 아래 실행 기록은 변경 당시 버전이며 원본 결과를 보존한다. 현재 입력은 A 일반 공격 / F 특수 공격 / S 이동·이동술이다.

## 구현 결과

자동 확률 발동을 **일반 공격 적중으로 준비하고 원하는 순간 수동 사용하는 특성 공격**으로 교체했다. 적의 배치와 공격 시점을 의도적으로 선택하게 하는 실험이며, 재미 개선을 검증했다고 주장하지 않는다.

- 일반 공격의 직접 적중은 행동 완료 시 충전 1회를 준다. 이동·빗나감·특성 공격·추가 시전·범위 피해는 충전하지 않는다.
- 기본 필요 적중: 더블 캐스트 4회, 관통 2회, 데미지 강화·넉백 3회. 준비된 사용권은 1회까지 보관하며 일반 공격으로 자동 소모되지 않는다.
- A는 일반 공격, Shift+A 또는 특성 아이콘은 수동 특성 공격이다. 방향 클릭으로 확정하면 소모한다. 확정 전 취소는 보존하고 확정 후 빗나감은 소모한다.
- 빈도 강화는 필요 적중을 즉시 낮추고 기존 충전을 보존한다. 웨이브 사이에는 보존하고 사망·20웨이브 완료·새 플레이에서는 초기화한다.
- 공격 예상 경로와 실행은 같은 첫 충돌 조회를 사용한다. 관통 이후는 유효 적중을 전제로 흐리게 표시한다. 추가 공격의 재조준에는 현재 보드를 사용한다.
- 적 hover는 룩의 고정 장전 열과 나이트·비숍의 조건부 가능한 위험을 구분한다. 표시 조회는 AI 실행·난수 소비·불길 생성을 하지 않는다.
- 왕의 차례는 원래 공격의 적 턴 **전에** 주는 기본 한 칸 이동이다. 추가 공격·이동술은 금지하고 우클릭으로 생략한다. 원래 적 턴은 이후 한 번 진행한다.
- 룩 이동술은 실행 시 중간 벽·적 점유를 다시 검사한다. 불길은 통과를 막지 않지만 불길 착지는 피해를 준다.
- 기존 uGUI에 충전·수동 사용 안내를 넣고 하단 HUD를 맵 폭에 맞춰 함께 배치한다. 시작 특성과 시작 증강의 같은 숫자 입력 중복 선택을 막았다.

13×13 내부 보드, 8방향, 20웨이브, 네 빌드의 기존 효과 계산, 적 능력치·보상·이동술 사용 횟수는 유지했다. 기획 근거: [확정 문서](../design/core-experience-review-2026-10-01.md), `GrowthAndRelics.md`, `CONTEXT.md`, `AGENTS.md`.

## 실행 결과와 한계

Unity 6000.4.0f1의 실제 SampleScene과 URP 실행 환경을 사용했다. 원래 작업창을 종료하지 않고 격리 복사본에서 네이티브 Play 검사를 실행했다.

원래 Unity 창에서도 Assets > Refresh 후 새 Play로 시작 선택·보상 선택·S 이동 표시를 확인했다. 시작 선택창이 사이드 패널보다 앞에 나오고, 하단 HUD가 맵을 가리지 않으며 선택 상태 안내가 어두운 배경의 밝은 글자로 표시됐다. 검사 후 Play를 종료했고 씬은 저장하지 않았다. 좁은 Game 뷰에서 글자는 함께 축소되므로 모든 화면 크기의 가독성을 보장한 것은 아니다. 편집 모드에는 씬에 저장된 구형 확률 문구가 보일 수 있지만 Play에서는 런타임이 새 문구로 바꾼다.

자동 런은 모두 사망으로 종료했다. 클리어 웨이브는 더블 캐스트 16, 관통 6, 데미지 강화 15, 넉백 14였다. 정책은 `heuristic-v5-manual`이며 과거 정책과 짝지은 비교가 아니므로 재미·밸런스 우열을 결정하지 않는다.

배치 Editor 시작 중 Unity Search 인덱서의 `ArgumentOutOfRangeException` 진단이 있었다. 게임 런타임 실패와 구분해 기록했다. 게임 검사에 실패는 없지만 Editor 전체에 진단이 전혀 없었다고 주장하지 않는다.

새 위험 테두리는 32 PPU·Point를 확인했다. 기존 픽스처의 `Frame_0`에는 40 PPU 설정이 남아 있으며 이번에 변경하지 않았다. 씬·패키지·렌더 설정·기존 GUID도 수정하지 않았다.

## 변경 파일과 설정

핵심 수정: `PlayerTraitSystem`, `Move`, `TurnProjectile`, `DirectionalActionIndicator`, `ChessMonsterBehaviour`, `MonsterSpawner`, `BishopFireTrail`, `GameHudController`, `RunProgressionSystem`, `RunProgressionUiController`, `RunProgressionCatalog`, `RunProgressionDescriptions`, `TraitOptionData`.

신규: `Assets/Codes/EnemyThreatPreview.cs`, `Assets/Editor/TacticalCoreValidation.cs`와 각각의 `.meta`. 기존 `ProgressionUsabilityValidation`·`RunBalanceValidation`도 새 규칙에 맞췄다. 기존 미커밋 변경은 보존했다.

추가 Inspector 설정은 없다. 기존 player·GameHUD 연결을 사용하며 위험 표시와 하단 그룹은 런타임에 생성한다. 추가 태그·레이어·Tilemap·Collider 설정도 없다. Unity UI·픽셀 퍼펙트 스킬은 기존 uGUI 재사용과 새 테두리의 32 PPU·Point 설정에 적용했다.

## 재현·후속 관찰

1. Play 후 시작 특성·증강 선택 → A로 직접 적중해 충전 확인.
2. 준비 후 A 일반 공격은 보관, Shift+A·특성 아이콘은 수동 선택. 우클릭 취소는 보존, 확정 후 빗나감은 소모.
3. 관통의 흐린 후속 경로와 실제 적중을 비교. 더블 캐스트 재조준 중 S 이동은 금지.
4. 룩·나이트·비숍 hover에서 고정/가능 위험 구분. 불길 생성과 착지 피해를 혼동하지 않는지 확인.
5. 왕의 차례에서 공격 금지·우클릭 생략 뒤 적 턴 한 번. 룩 이동은 중간 적 통과 금지·빈 불길 착지 허용.

`Tools > Playtest > Validate Tactical Core`로 핵심 검사를 실행한다. 상태를 구성하는 검사이므로 진행 중인 플레이에는 실행하지 않는다. 배치 진입점은 `TacticalCoreValidation.RunBatch`이며 비동기 검사라 `-quit`·`-nographics`를 붙이지 않는다.

아직 미검증인 것은 인간의 재미다. 다음 플레이에서 **특성을 보관할 이유**, **사선을 만들기 위한 이동과 강한 공격의 연결**, **도망-공격 반복 감소**를 관찰한다. 새 콘텐츠·수치 조정 전에 이 세 항목으로 가설을 평가한다.
