# 모바일/Safari 테스트용 Web 빌드 검증

## 결과

- Unity 6000.4.0f1 Web 빌드 성공. BuildReport의 압축 파일 총량은 13,779,724 bytes(약 13.1 MiB). 로컬 HTTP 서버가 압축을 풀어 보내므로 실제 전송량은 이보다 크다.
- [모바일 입력 어댑터](mobile-adapter-2026-10-02.txt): 16개 조건 실행. 통제된 Unity Editor 픽스처와 세로 화면 기하 검사이며 실기기 검증이 아니다.
- [PC 전투 회귀](mobile-pc-regression-2026-10-02.txt): 45개 조건. F, 준비/취소/소모, 추가 공격, 무료 이동, 룩 이동, 적 조건부 위험 표시 등.
- 독립적인 Chrome 헤드리스 터치 에뮬레이션: 25개 조건 실행·통과. 게임 스크립트 예외와 브라우저 console error는 채집되지 않았다. iPhone/Safari의 결과가 아니다.

## 브라우저에서 실행한 내용

시작 특성·시작 증강 선택, 상세 표시/닫기, 미충전 특수공격 거부, 공격 방향 미리보기, 취소, 확정 공격 1회=적 턴 1회, 중복 확정 방지, 강화 목록의 입력 차단, 메뉴 정지/재개, 인접 칸 이동 미리보기/확정, 인공적인 `visibilitychange`를 통한 정지 훅과 명시적 재개, 세로 375×667/390×844 리사이즈, 가로 화면의 세로 회전 안내를 확인했다.

위협도·승률·사람의 재미를 검증한 실험이 아니며, 모바일로 20웨이브를 완주한 결과도 아니다. 실제 iOS 앱 전환·메모리 회수는 미검증이다.

## 발견·수정한 문제

부분 카메라 뷰포트 밖이 매 프레임 지워지지 않아 닫힌 보상 카드나 리사이즈 전 글자가 남았다. `MobilePlaytestController`에 보드를 덮지 않는 불투명 여백 패널 4개를 추가했다. 공격 경로 표시와 작은 세로 화면 캡처를 재확인하고 잔상이 사라진 것을 시각 검수했다. 배경의 raycastTarget=false로 조작을 차단하지 않으며 추가 카메라·저장 씬 변경은 필요 없다.

자동 검사의 고정 400ms 대기는 소프트웨어 GPU의 느린 프레임과 설명을 닫은 동일 프레임의 클릭 관통 방지에 맞지 않았다. 검사를 상태 대기로 변경했으며 게임의 입력 보호는 제거하지 않았다.

## 재현·기록

- 빌드: `Assets/Editor/MobileWebBuild.cs`
- Editor 입력 검사: `Tools > Playtest > Validate Mobile Touch Adapter`
- 브라우저 검사: `Tools/mobile-playtest/browser-smoke.mjs`(제공 Playwright와 로컬 Chrome 사용. 추가 패키지 설치 없음)
- 실행 HTML/서버: `Tools/mobile-playtest/index.html`, `serve.mjs`
- 조작·Inspector·서버 실행: [모바일 작업 내용](../design/mobile-safari-playtest.md)
- 브라우저 원본 로그·화면: `Builds/MobileWeb/verification/`. 빌드 결과물이므로 Git 대상에서 제외한다.

검증한 모바일 어댑터의 SHA-256:
`353862466d4a814565461f3ad665f20b9c85e92341bf33bac90a504197d99b60`
원본 프로젝트와 격리한 빌드용 복사본에서 일치했다. 해당 파일의 해시이며 저장소 전체의 커밋 식별자가 아니다.

## 주의·다음 실기기 확인

HTTP 환경의 브라우저 Cache API/Webcam 미지원 안내와 소프트웨어 GPU에서 사용하지 않는 URP 숨김 셰이더 경고는 기록됐다. 실기기의 렌더링·성능을 보장하는 결과가 아니다.

실제 아이폰에서 접속, 초기 로딩, 탭 정확도, 벽 근처 이동술, 위험 표시, 후반 효과량, 화면 회전, 앱 전환을 확인한다. 기존 상세 문구 일부에는 PC A/S/F 표기가 남아 있다(모바일 공격/이동/특수공격 버튼에 대응). 브라우저 새로고침·iOS 탭 폐기 후 런 복원은 포함하지 않는다.
