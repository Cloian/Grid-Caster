# 2026-09-30 밸런스 적용 및 실제 런 검증

## 결과

Unity 6000.4.0f1에서 저장된 SampleScene 복사본으로 게임 코드를 실제 실행했다. 조정용 시드 1000번대와 분리한 **2000~2023, 특성별 24회, 총 96회**에서 20웨이브 클리어는 **29/96 (30.2%)**였다. 아래는 인간 승률이 아니라 공개된 보드를 읽는 고정 휴리스틱 봇의 결과다.

|---|---:|---:|---:|---:|---:|---:|

| 관통 | 9/24 | 37.5% | 21.2~57.3% | 24/24 | 11 / 4 | 18 |
| 데미지 강화 | 13/24 | 54.2% | 35.1~72.1% | 24/24 | 11 / 0 | 20 |
| 넉백 | 2/24 | 8.3% | 2.3~25.8% | 23/24 | 22 / 0 | 15 |

96회 모두 4웨이브를 통과했다. 사망 62회와 턴 제한 5회도 클리어율 분모에 포함했다. 제한은 웨이브당 입력 선택 200회 또는 런 전체 3500회이며, 회피 반복으로 끝나지 않은 결과를 사망으로 바꾸지 않았다.

### 전설을 선택하지 않는 비교

동일한 최종 수치와 봇으로 시드 2000~2007을 다시 실행하되 공개된 전설 제단은 선택하지 않았다. 제단 추첨을 다시 돌리거나 희귀 유물을 강제로 지급하지 않았다. 두 제단이 모두 전설이면 유물을 포기하고 정상 일반 보상을 받는다.

| 시작 특성 | 전체 등급 허용, 같은 8시드 | 전설 제단 회피, 같은 8시드 |
|---|---:|---:|
| 더블 캐스트 | 1/8 | 2/8 |
| 관통 | 4/8 | 5/8 |
| 데미지 강화 | 4/8 | 3/8 |
| 넉백 | 0/8 | 2/8 |

전설 회피는 총 12/32 (37.5%) 클리어, 사망 19회, 턴 제한 1회였다. 네 빌드 모두 전설 없는 실제 완주 사례가 존재한다. 본 실험에서도 전설 없이 완주한 런은 더블 2, 관통 5, 데미지 8, 넉백 2회였다.

제단 회피는 경로·피해·공격 순서와 이후 RNG 소비를 바꾸므로 이 표를 유물 등급의 인과 효과로 해석하지 않는다. 전설이 항상 더 좋거나 기본 빌드의 필수 조건이라는 주장은 지지되지 않는다.

원본: [전설 회피 32회](balance-no-legendary.json).

## 적용한 수치와 규칙

| 항목 | 변경 |
|---|---|
| 기본 공격 / 적 체력 / 플레이어 시작 체력 | 1 / 3 / 10 유지. 테스트 원본에서도 확인 |
| 클리어 기본 회복 | 최대 체력 10%→30%, 올림. 체력 10이면 1→3 회복. 1~19웨이브에만 적용 |
| 회복 호흡 | +5%p 대신 정수 +1→+2. 두 번째 중첩에도 실제 회복 증가 |
| 나이트 | 일반 런 1→최소 2턴 간격, 다음 준비/도약 상태 공개. 독립 패턴 테스트는 기존 1턴 유지 |
| 고정 적 조합 | 5~7웨이브 8/9/10→6/7/8명, 10웨이브 14→8명, 20웨이브 25→18명. 새 기믹 해금은 4/8/12 유지 |
| 메아리 탄두 | 추가 시전 직격 피해 +1(중첩하지 않음), 추가 관통 1→2명 |
| 긴 충격 | 넉백 발동 직격 피해 +1, 밀기 거리 +1 |
| 반향 압박 / 충격 봉쇄 | 대상 2→3명. 충격 봉쇄는 처치·이동 불가에도 적용 |
| 과충전 | 1중첩은 발동 직격 3, 2중첩은 직격 3 유지 + 첫 적중 주변 피해 1 |
| 특성 완성 | 백 크기 감소 제거, 추가 시전 피해 / 추가 관통 피해 / 첫 적중 범위 / 서로 다른 적 봉쇄로 분기 |
| 예리한 마력 | 상시 피해 대신 특성 발동 공격의 첫 직격 +1, 최대 체력 -1 |
| 유리 심장 | 최대 체력 -3→-2, 모든 직격 +1, 직격 초과 피해 최대 2를 주변 한 명에게 한 번 전달 |
| 다른 유물 | 피의 매듭 회복 2, 봉합 바늘 최대 2회/웨이브, 폭렬 핵 범위 피해 2, 기습 문장 첫 직격+범위, 파성추 이동 불가 시에도 봉쇄 |
| 추첨 / 이동 숙련 | 미획득 전용 부품을 보장 자리에서 우선, 무효 상급 카드 제외, 이동술 교체 시 레벨 보존, 16웨이브 최소 희귀 |

보상 주기는 짝수 웨이브마다 한 선택으로 유지했다. 공격력 무한 중첩, 성장에 따른 적 실시간 보정, 새 게이지·필살기·직업·영구 성장은 추가하지 않았다.

수치 외 오류도 수정했다. 소비 중인 발동 백을 무관한 강화로 다시 추첨하지 않는다. 같은 범위 효과는 행동당 같은 적을 한 번만 타격한다. 저장 피해는 출처별 합산 후 첫 실제 직격에만 적용한다. 0이 된 피해는 다음 방어를 소모하지 않는다. 추가 시전·왕의 무료 이동이 남았을 때 다음 웨이브가 시작되는 경쟁 조건을 막았다.

정확한 21유물·강화 목록은 [성장 규칙](../../GrowthAndRelics.md), 20웨이브 조합은 [웨이브 표](../../ChessWaves.md), 선택 예산과 전설 없는 최종 빌드 산출은 [빌드 검토](../design/build-balance-2026-09-30.md)를 따른다.

## 검증 방식과 한계

봇은 실제 `Move.TryPerformAction`으로 공격·이동을 입력하고 실제 AI·예약·불길·피해·사망·웨이브 종료를 실행한다. 보상도 실제로 제시된 카드 중에서만 선택한다. 발동 백의 남은 결과·미래 RNG·적의 내부 예약을 보지 않는다. 현재 위치, 체력, 공개된 나이트 행동 상태와 룩 사선만 사용한다. `Time.timeScale`과 이동 연출 속도만 올려 검사 시간을 줄였으며 체력·공격력·적 처치·보상은 우회하지 않았다.

정책은 `heuristic-v4`: 장거리 직격, 단순 두 수 추격 예상, 현재 위험 회피, 나이트 이동술·범위·봉쇄 강화 우선, 제단 접근을 사용한다. 다중 턴 최적 탐색, 미래 발동 카운팅, 넉백 충돌 각도 최적화, 유물별 장기 효용 평가는 하지 않는다. 입력 선택 횟수는 회전 거울의 추가 방향과 왕의 무료 이동을 포함하므로 실제 적 턴 수인 `worldTurns`와 구분한다.

데미지 강화는 이 정책에서 가장 안정적인 입문 빌드였고, 넉백은 여전히 낮은 지표를 보였다. 그러나 24회 표본의 신뢰 구간은 넓고 전설 회피에서는 결과가 달라졌다. 단일 봇의 수치를 강제로 동률로 맞추기 위해 공격력을 계속 올리지 않았다. 네 빌드의 정상 작동·전설 없는 완주 가능성을 확인한 **1차 밸런스**이며, 인간이 충돌 각도와 위험한 제단을 선택하는 실제 플레이 관찰이 다음 검증이다.

### 별도 효과·회귀 검사

* 효과/최종 빌드 단위 검사 34건과 16웨이브 제단 128시드 검사, 총 162개 assertion 통과. URP 및 32 PPU·Point 확인 기록을 포함하면 보고서의 `checks`는 163개다.
* 네 최종 예시는 각각 일반 6선택·상급 4선택 예산을 지키며 더블의 추가 피해 3, 관통의 추가 대상 피해 2, 데미지의 직격 3+서로 다른 범위 3, 넉백의 직격 2·밀기 2·최대 5명 서로 다른 봉쇄를 확인했다.
* 기존 이동·점유·공격·체스 패턴·UI 생성·1~13웨이브 보상 연결과 20웨이브 구성 회귀 520건 통과. [전체 회귀 결과](chess-balance-regression.txt).
* 위 픽스처는 의도적으로 체력·보유 부품·적 배치를 조작하며 **승률 표본에는 넣지 않는다**. 20웨이브 실제 종료는 독립 런의 클리어 결과로 검증했다.
* Unity Editor Search의 시작 인덱싱 `ArgumentOutOfRangeException`이 있었다. 게임 스크립트가 없는 알려진 시작 오류만 `editorDiagnostics`에 보존해 분리했으며, 그 외 실행 중 Error/Exception/Assert는 밸런스 검증 실패로 처리한다. 게임 C# 컴파일 오류는 없었다. 실제 마우스 조작·육안 UI QA와 인간의 재미는 별도 검증이다.
* Unity CLI 스킬의 배치 실행 지침을 적용하되 비동기 Play 검사를 위해 자동 `-quit` 없는 네이티브 에디터 실행을 사용했다. Unity UI/IMGUI 스킬은 기존 도약 상태 표시와 GUIStyle 캐시에, 2D Pixel Perfect 스킬은 URP·32 PPU·Point 검사에 적용했다. 렌더러·아트·패키지는 변경하지 않았다.

### 조정 이력

첫 자동 정책 v1/v2는 회피 반복이 많아 승률 근거에서 제외했다. v3 16회는 0클리어·대부분 4~5웨이브 사망을 확인했지만 최종 v4와 정책이 달라 통제된 전후 비교가 아니다. v4에서 나이트 간격·고정 조합·회복을 차례로 바꾸고, 이후 약한 두 빌드의 기본 부품을 보완했다. 조정용 시드 1000~1007의 마지막 결과는 더블 4/8, 관통 1/8, 데미지 3/8, 넉백 3/8이었다. 최종 승률에는 이 조정 표본을 합치지 않았다.

중간 JSON은 `balance-tuning*`에 보존했다. `balance-tuning07-startup-failed.json`은 Editor Search 오류로 0런에서 중단된 진단 기록이며, 재실행 결과와 혼동하지 않는다.

## 재현과 코드 일치

마지막 카드 문구에서 첫 직격·직접 처치·0칸 밀기를 명확히 한 뒤 본 실험을 다시 실행했다. 설명 변경 전 기록은 `*-before-labels.json`에 남겼다. 96회 결과는 입력 수·보상·체력까지 동일했다.

원본 에디터의 저장하지 않은 작업을 보존하기 위해 Assets·Packages·ProjectSettings만 복사한 `/tmp/GridCasterBalance.VpXsE3`에서 실행했다. 별도 패키지 설치나 원본 씬 저장은 하지 않았다. 원본과 복사본의 아래 해시가 일치한다.

* 판정/표시 12개 C# 파일과 SampleScene 텍스트를 결합한 `sourceHash`: `7152fceed5051d5b4de0dfdab092f1484157bae0b05f08e576fe5b5ad2ced875`.
* 테스트 파일 `policyHash`: `6509ff9abeff2a0eb30ed0291069455a3f1be75cdea0c883a901edbe76f8fc30`.
* 해시 대상의 정확한 목록/결합 순서는 `RunBalanceValidation.SourceHash`에 있다. 전체 프로젝트 해시라는 의미는 아니다.

Play 종료 후 `Tools > Playtest > Validate Run Balance`에서 기본 32회 테스트를 실행할 수 있다. 배치 검증은 출력 경로가 지정된 JSON 요청을 만들고 다음과 같이 호출한다. 이미 실행 중인 원본 에디터와 같은 프로젝트를 배치로 다시 열지 않는다.

```sh
/Applications/Unity/Hub/Editor/6000.4.0f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -nographics -projectPath /tmp/GridCasterBalance.VpXsE3 \
  -executeMethod RunBalanceValidation.RunBatch \
  -balanceRequest /tmp/GridCasterBalance-holdout.json \
  -logFile /tmp/GridCasterBalanceHoldout.log
```

요청 필드: `label`, `outputPath`, `firstSeed: 2000`, `seedsPerTrait: 24`, `allowRelics: true`, `validateMechanics: true`. 전설 회피 비교는 `avoidLegendary: true` 및 `seedsPerTrait: 8`이다. 비동기 Play 검사를 끝내기 전에 종료되지 않도록 `-quit`을 붙이지 않는다.
