# 첫 스테이지 판단·빌드 플레이테스트

## 질문과 경계

핵심 질문은 ‘위협을 읽고 위치·공격 순서를 바꾼 결과, 선택한 빌드로 더 좋은 한 수를 만들었는가’다. 단순 클리어 여부나 처치량을 재미 점수로 쓰지 않는다. 현재 내부 13×13, 8방향, 네 시작 특성, 20웨이브를 유지한다. 보스·새 속성·새 스테이지를 먼저 추가하지 않는다.

PC의 기존 Unity Editor에서 `SampleScene` Play를 사용한다. 웹 링크·서버가 필요하지 않다. 일반 플레이는 A 공격, S 기본 이동/이동술, F 준비한 특수공격, 마우스 방향 미리보기·좌클릭 확정·우클릭 취소다.

20웨이브 클리어와 사망 뒤에는 결과 패널을 표시한다. ESC는 패널만 숨겨 전장을 복기하며 종료된 전투를 재개하지 않는다. 다시 ESC로 결과를 표시하거나 버튼으로 같은 스테이지의 새 빌드를 시작한다. 클리어 기록의 영구 저장이나 다음 스테이지 진입은 아직 없다.

## 비교 조건

처음에는 각 빌드를 한 번씩 플레이한다. 가능하면 같은 사람이 플레이 순서를 바꿔 다시 비교한다. 4회는 방향을 잡는 탐색이며 표본이 작아 선호도·승률을 일반화하지 않는다.

보상이나 적 배치를 통제하지 않은 정상 런은 ‘같은 조건 실험’이 아니다. 기계적 효과는 통제된 전술 검사로, 선택 이유와 쾌감은 정상 사람 플레이로 각각 확인한다. 실험 중 체력·피해·웨이브 물량·이동술 제한을 동시에 바꾸지 않는다.

| 빌드 | 보고 싶은 판단 | 반증 신호 |
| --- | --- | --- |
| 더블 캐스트 | 첫 처치 뒤 다른 방향 위협을 처리하려고 재조준 | 추가 공격을 계속 같은 적에게 반복할 뿐 순서 선택이 없음 |
| 관통 | 적을 같은 공격선에 놓고 준비한 관통을 보관/사용 | 뒤쪽 적 배치와 관계없이 준비 즉시 사용하는 것이 항상 최선 |
| 데미지 강화 | 체력이 낮은 직접 대상을 골라 남은 피해를 인접 적에게 전달 | 추가 피해만 체감하고 초과 전달의 대상 선택을 전혀 이해하지 못함 |
| 넉백 | 벽·적 충돌·봉쇄로 안전한 공격 기회를 마련 | 넉백 위치와 무관한 자동 피해·봉쇄로만 진행 |

## Unity 로컬 기록

`Tools > Playtest > Record Local Play Sessions`를 켠 뒤 SampleScene을 Play한다. 이 기능은 기본 꺼짐인 Editor 전용 도구다. 컴포넌트를 붙이거나 Inspector·태그·레이어를 설정할 필요가 없다. 제품 빌드에는 들어가지 않고, 네트워크 전송도 하지 않는다.

Play 종료 또는 스크립트 재컴파일 시 `docs/verification/play-sessions/session-날짜-시각.json`에 새 파일로 저장한다. 다시 메뉴를 누르면 기록을 끄며 기존 파일은 삭제하지 않는다. Unity 앱을 종료하면 세션 설정은 유지되지 않는다.

기록하는 내용:

- 일반/특수공격, 기본 이동/이동술, 공격 뒤 왕의 차례 추가 이동 횟수.
- 웨이브·적 턴 수, 위치·체력·특성 충전, 이동술 종류/레벨.
- 강화·유물 변경과 적의 위치·체력, 불길 개수.
- 완료된 공격의 시전 수·직접 적중 수·마지막 방향과 원래 발사 위치.

제약: 기록은 켠 시점부터만 관찰한다. `MoveCompleted` 구독 순서 때문에 행동 알림 시점에 적 계획이 이미 시작됐을 수 있으므로 ‘적 행동 직전 전체 보드’로 해석하지 않는다. 입력 없이 구상한 의도, 취소한 조준, 모든 추가 시전 방향, 정확한 사망 가해자, 재미는 자동으로 추정하지 않는다. 턴 완료 전 불길로 사망한 이동은 완료 행동 카운트에 포함되지 않을 수 있다. 제어된 검사로 생성한 예시는 인간 플레이 자료가 아니다.

## 플레이 직후 짧은 기록

```
빌드 / 주요 강화·유물 / 이동술:
읽기 어려웠던 타일·위험·버튼:
가장 좋았던 한 수 (위협 → 선택한 위치·순서 → 결과):
특수공격을 지금 쓴 이유 또는 보관한 이유:
같은 이동·공격을 반복한 웨이브와 원인:
보상 설명과 실제 결과가 달랐던 사례:
사망 원인 또는 클리어 직전 긴장감:
다음 런에서 달리 해보고 싶은 선택:
```

처음부터 정답이나 빌드 운용법을 설명하지 않는다. 혼란을 본 뒤 상세 설명을 읽었을 때 해결되는지 확인한다. 마지막 비숍을 상대로 대각선 이동만 반복한다면 기본 한 칸 이동으로 색/공격선을 바꾸는 선택을 이해하는지 관찰한다. 이를 근거로 자동 피해·추적 공격·강제 처치를 추가하지 않는다.

## 다음 결정

규칙 불일치 → 재현/수정/회귀. 정보 부족 → 필요한 정보만 보강. 선택이 같음 → 중복 효과 통합·축소 또는 조건 한 가지 조정. 재미·판독성은 미검증으로 남긴 뒤 실제 기록으로 평가한다. 각 빌드의 선택 이유와 큰 결과가 연결되면 그 다음에 보스의 한 패턴 그레이박스를 설계한다.
