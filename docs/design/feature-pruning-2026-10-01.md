# Grid-Caster 기능 분류와 덜어내기 검토

작성일: 2026-10-01. 대상: 현재 Grid-Caster의 SampleScene, 런타임 코드, 기획 문서.

**이 문서는 검토안이다. 분류가 곧 삭제·구현 확정은 아니다.** 이번 변경은 시작 조작 안내와 그 회귀 검사뿐이며 전투·성장·보상을 삭제하거나 변경하지 않았다.

## 1. 플레이어에게 약속할 경험

작은 전체 보드에서 적의 규칙을 읽고, 이동과 공격 중 하나를 선택해 위험을 해결한다. 한 런 안에서는 다른 빌드를 만들고, 실패하면 원인을 이해해 다시 도전한다.

따라서 발전의 기준은 콘텐츠 수가 아니라 다음 네 가지다.

1. **이해:** 플레이어가 지금 할 수 있는 행동과 결과를 알 수 있는가?
2. **판단:** 기존과 다른 선택의 이유가 생기는가?
3. **보상감:** 좋은 판단과 성장이 화면에서 분명하게 느껴지는가?
4. **재도전:** 다음 런에 다른 선택을 할 이유가 있는가?

새 기능의 설명·관리·반복 클릭 비용도 함께 본다. 편의 기능은 판단을 대신하는 것이 아니라 판단에 필요한 정보를 보여주는 역할이어야 한다.

### 객관성의 범위

- **확인한 사실:** 코드·데이터의 효과와 입력, 화면 구성, 현재 제공되는 콘텐츠.
- **설계 판단:** 그 구조가 플레이어에게 줄 수 있는 이점과 부담. 사실과 분리해 적었다.
- **미검증:** 실제 재미·선호도·체감 난이도·적절한 런 길이. 이번에는 사람 대상 테스트를 하지 않았다.

표의 우선순위는 사용성 원칙과 현재 구조를 근거로 한 임시 판단이다. 실제 플레이어의 사용률이나 설문 결과를 만들어 붙이지 않는다. 기존 자동 런의 승률도 사람의 승률로 취급하지 않는다.

조작을 기억시키기보다 필요한 위치에 보여주는 방식은 [NN/g의 Recognition Rather Than Recall](https://www.nngroup.com/articles/recognition-and-recall/)을 참고했다. 덜어내기는 정보 자체의 삭제가 아니라 필요한 순간에 드러내는 방식도 포함한다. [NN/g의 Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) 참고. 이것들은 게임 재미에 대한 실험 결과가 아니다.

| 순서 | 기능 / 목적 | 기대하는 플레이어 경험 | 위험 / 더 단순한 대안 | 분류 |
| --- | --- | --- | --- | --- |
| 1 | **짧은 시작 조작 안내** | A/S를 누른 뒤 무엇을 클릭하는지 바로 이해 | 긴 튜토리얼·확인 버튼을 추가하지 않고 기존 시작 선택 화면 이용 | **Supporting · 이번에 적용** |
| 2 | **실제 결과와 맞는 공격 미리보기** | 관통 대상과 불길 제거를 모르고 실수하지 않음 | 최종 피해·모든 발동을 몰아서 표시하지 말고 확정 경로/확률 효과 구분 | **Core · 최우선 후속 검토** |

| 5 | **짧은 런 결과 요약** | 무엇을 들고 어디에서 실패했는지 기억하고 다른 빌드 선택 | 전체 전투 리플레이 대신 시작 특성·주요 유물·도달 웨이브·마지막 피해 원인 | **Supporting** |

| 8 | **피격·다중 적중·특성 발동의 짧은 소리/연출** | 좋은 공격과 성장의 결과가 더 선명함 | 긴 비행·강제 슬로모션·큰 흔들림보다 짧고 취소 가능한 피드백 | **Polish · 규칙 안정 후** |
| 9 | **런 중단/재개** | 한 번에 끝내지 못해도 부담 없이 복귀 | 사람 테스트로 실제 세션 길이를 먼저 측정; 필요 없으면 만들지 않음 | **Supporting 조건부** |
| 10 | **기본 접근성·설정** | 작은 글자나 색 구분 때문에 규칙을 놓치지 않음 | 음량·글자 가독성·키 표시부터. 새로운 설정 화면이나 리매핑 전부를 먼저 만들지 않음 | **Supporting · 실제 불편 관찰에 맞춰** |

현재 공격 미리보기 코드는 첫 몬스터 또는 벽에서 끝난다. 실제 관통은 추가 구간을 처리한다. 따라서 미리보기 확장이 단순 편의 이상의 검토 대상이다. 이번 변경에서 그 판정이나 미리보기 로직은 수정하지 않았다.

## 4. 간소화·통합 후보 — 먼저 줄일 곳

### 4.1 네 빌드가 모두 폭발과 봉쇄를 얻는 구조

현재 추가 시전, 관통, 데미지 강화, 넉백 모두 범위 피해 또는 주변 행동 봉쇄로 확장될 수 있다. 보조 효과의 존재 자체는 문제가 아니지만, 모든 빌드의 후반 결과가 `여러 적에게 피해 + 여러 적 봉쇄`로 비슷해질 위험이 있다. 실제 수렴 여부는 사람 플레이로 확인해야 한다.

**권장 방향:** 공통 생존 보조는 소수만 남기고 전용 성장의 주효과는 다음과 같이 읽히도록 정리한다.

- 더블 캐스트: 추가 공격 기회·두 번째 방향.
- 관통: 일렬 배치·한 사선의 여러 대상.
- 데미지 강화: 강한 한 적의 처치 턴 단축.
- 넉백: 거리·벽·다른 적과의 충돌.

봉쇄를 전부 삭제하자는 뜻은 아니다. 어느 행동 조건에서 얻는지 다른 효과 하나를 남기고, 같은 빌드의 거의 같은 발동 조건과 결과를 가진 항목부터 비교한다.

## 5. 현재 강화·유물 목록별 분류

`유지`: 독립적인 역할이 확인됨. `개선`: 필요하지만 정보 또는 역할이 더 명료해야 함. `통합 후보`: 다른 효과와 중복 여부를 우선 비교. 어느 분류도 실제 선호도 검증을 뜻하지 않는다.

## 7. 괜찮지만 지금 보류할 기능

- **고유 중간보스/최종보스:** 일반 다섯 적과 빌드가 안정된 뒤, 기존 규칙을 새 조합으로 읽게 하는 패턴부터. 현재 10/20웨이브 혼합전은 유지한다.
- **새 스테이지·날씨·새 지형:** 1스테이지의 세션 길이와 반복성이 확인된 뒤. 한 스테이지 안에서 맵을 바꾸지 않는 기존 방향 유지.
- **새 몬스터:** 기존 다섯 종류가 못 만드는 구체적인 판단이 있을 때만. 체력·속도만 다른 적은 우선하지 않는다.
- **상점·이벤트 방:** 보상 선택과 제단이 충분히 다른 선택을 만드는지 먼저 확인. 성장 선택 화면을 또 늘리는 것부터 시작하지 않는다.
- **직업·동료·스토리 RPG:** 지금의 작은 보드 생존 게임과 작업 범위가 크게 달라짐. 시작 특성과 이동술로 재도전 차별화를 먼저 검증.
- **도감·업적·외형 해금:** 핵심 루프가 재미있다는 확인 후. 첫 적 이해는 긴 도감보다 짧은 현장 설명으로 해결.
- **무한 모드·추가 난이도·데일리 시드:** 20웨이브 끝까지 즐긴 플레이어가 반복할 다른 도전을 원할 때.
- **모바일·컨트롤러·플랫폼 확장:** 현재 PC 조작과 가독성 검증을 우선. 별도 입력 설계를 지금 핵심 작업에 겹치지 않는다.

## 8. 덜어내기 검증 방법

처음 플레이하는 목표 플레이어와 반복 플레이어를 구분한다. 6~8명의 짧은 관찰은 문제 발견용이지 모집단의 객관적 선호도 확정용이 아니다.

1. 첫 판: 별도 설명 없이 시작 안내만 보고 A/S 선택·호버·클릭을 할 수 있는지 관찰. 공격할 적을 클릭했는데 안 되는 혼란도 기록한다.
2. 첫 피해: 왜 맞았는지 설명할 수 있는가? 설명 못 하는 실패를 난이도 부족으로 해결하지 않는다.
3. 보상 선택: 선택/포기 이유를 말할 수 있는가? 이름만 다른 동일 역할 후보가 반복되는가?
4. 후반: 이동술을 쓰는 이유가 각도·안전 확보인지, 다른 행동을 할 수 없어 같은 도주를 반복하는지 관찰한다.
5. 런 종료: 빌드의 차이와 실패 원인을 기억하는가? 다음 런에 다른 특성을 자발적으로 고르는가?
6. 후보 제거 비교: 겹치는 봉쇄·회복 효과 하나만 제외한 버전을 같은 난이도 조건과 비교한다. 선택 수를 줄인 효과와 단순 약해진 효과를 구분한다.

기능을 뺄 신호: 선택 이유가 달라지지 않음, 설명을 기억해도 쓸 이유가 없음, 자동으로 누르는 선택만 늘어남, 다른 시스템과 결과가 거의 같음. **낮은 사용률만으로 삭제하지 않는다.** 드문 상황을 해결하는 효과는 낮은 사용률이어도 가치가 있을 수 있다.

## 9. 권장 다음 개발 순서

**조작 이해 → 실제 결과를 맞히는 미리보기 → 적/피해 원인 가독성 → 겹치는 성장 효과 비교 → 런 길이와 웨이브 완급 측정 → 공격 형태 유물 하나의 재미 테스트 → 짧은 피드백 연출 → 추가 콘텐츠.**

당장 ‘몬스터 더 많이, 유물 더 많이, 스테이지 더 많이’로 확장하지 않는다. 다만 실제 반복자가 콘텐츠 부족을 문제로 말하면 그 결과를 근거로 우선순위를 바꾼다.

- 다른 기존 능력, 추가 시전 잠금, 적 턴, 보상 흐름은 변경하지 않았다.
- 직접 확인: `Assets/Scenes/SampleScene.unity` Play → 시작 카드 아래 네 줄 확인 → 특성 선택 후 안내가 사라짐 → 시작 강화 선택 → A 및 화살표 호버/좌클릭 → S 및 노란 착지점 좌클릭 → 우클릭 취소.
- 별도 팝업·확인 클릭·재표시 단축키·강제 튜토리얼은 만들지 않았다. 게임 중 기존 간단한 조작 HUD 안내는 유지한다.
- 자동 검증은 글자 생성·네 줄 배치·카드 비중첩·클릭 비차단·시작 후 비노출과 기존 보상 상세창 회귀를 검사한다. 자동 검증이 실제 화면을 사람이 읽은 테스트나 재미 검증을 대신하지 않는다.

### 실행한 검증

Unity `6000.4.0f1`의 배치 Play에서 `ProgressionUsabilityValidation.RunBatch`를 실행했다. 최종 실행은 종료 코드 0, `REWARD_USABILITY_PASS`이며 기존 회귀를 포함한 **1,010개 검사 항목**을 통과했다. 이것은 독립적인 1,010회 플레이가 아니라 한 검증 실행 안의 조건 검사 개수다.

시작 안내의 네 줄 글자 생성, 네 카드와 비중첩, 클릭 비차단, 선택 후 비노출을 확인했다. 기존 보유 증강·유물·이동술 상세 클릭, 레벨 설명, 최대 중첩 후보 제외, 위험 제단 등급 보장 회귀도 통과했다. 최종 실행 로그에 C# 컴파일 오류는 없었다. 시작 과정의 라이선스 토큰 갱신 경고는 있었으나 Play 검증과 정상 종료를 막지 않았다.

첫 실행의 검사식이 리치 텍스트 색상 코드의 `F`를 구형 F키 안내로 잘못 인식했다. 입력 설명의 실제 `F키` 문자열 검사로 수정한 뒤 재실행해 통과했다. 런타임 입력 버그로 분류하지 않는다.

결과: [`../verification/startup-controls-usability-2026-10-01.txt`](../verification/startup-controls-usability-2026-10-01.txt). 이번에는 직접 마우스로 플레이하거나 렌더된 화면을 시각적으로 확인하지 못했으므로, 다양한 창 크기의 실제 읽기 편함은 위 직접 확인 절차로 추가 검증해야 한다. 새 GUI Unity 창, 씬 재생성, 신규 패키지는 만들지 않았다.
