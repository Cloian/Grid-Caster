# 효과음 제작 방식 조사와 v2 적용 — 2026-10-03

## 현업의 일반적인 제작 흐름

팀과 예산에 따라 도구와 역할은 달라진다. 게임의 소리 방향을 정하고, 필요한 사건을 목록화한 뒤, 재료를 확보해 편집하고, 게임에 연결한 후 반복 청취하며 믹스를 조정하는 과정이 일반적이다. REAPER·Pro Tools·Nuendo 같은 DAW와 엔진/미들웨어는 이 과정에서 사용되는 도구다.
출처: [Game Audio Explained — 현업 기여자들의 가이드](https://www.asoundeffect.com/gameaudioexplained/).

1. **무엇을 전달할지 정한다.** 발사 확인, 위험 예고, 재질, 체력 손실 등의 역할과 실제 발생 조건을 정의한다.
2. **재료를 확보한다.** 직접 녹음한 Foley/물체 소리, 녹음 라이브러리, 합성 소리를 조합한다.
3. **편집하고 레이어를 구성한다.** 짧은 시작 타격, 소리의 몸통, 움직임, 필요한 잔향을 분리해 조합한다. 모든 효과음에 모든 레이어가 필요한 것은 아니다.
4. **재질과 동작을 만든다.** 필터/EQ, 음높이, 길이, 역재생, 입자 편집, 공명, 지연 등을 목적에 맞게 쓴다.
5. **게임에 연결하고 반복을 확인한다.** 발사와 명중의 시간 차이, 동시 재생 수, 반복 피로, BGM과의 충돌, 플레이어 피격 정보의 가청성을 조정한다.

마법 소리도 합성만으로 만드는 것은 아니다. 사운드 디자이너 Vincent Fliniaux는 실제 비닐 소리를 녹음한 뒤 음높이·역재생·레이어·처리를 거쳐 전기 마법을 만든 과정을 설명한다.
출처: [Magic Elements 제작자 인터뷰](https://www.asoundeffect.com/magic-sound-effects-library/).

갑주·옷·발걸음·스침 등의 Foley를 장면 동작과 연결하는 사례는 [Dan Mellins-Cohen의 제작 시연](https://www.krotosaudio.com/krotos-sound-design-from-the-sofa-tutorial-series/)에서도 확인했다.

## Grid-Caster에 적용한 방향

현재의 짧은 턴 행동을 명확히 구분하는 것이 목표다. 빽빽한 보드에서 계속 큰 폭발음이 겹치는 방향은 피하고, 각 사건의 핵심 재질과 시작점을 분명히 만든다.

이전 v1은 공통 하강 합성음·잡음·공명 구조에 많이 의존했다. v2에서는 CC0 소재를 확보하고 각 역할의 기반 재료부터 다르게 편집했다.

| 종류 | 주된 소재 | 보조 설계 |
| --- | --- | --- |
| 마법 | 천 스침, 책장, 유리, 종 | FM·입자·역재생·공명 |
| 생물 명중 | 가죽, 천, 부드러운 충격 | 소량의 마법·의복 |
| 단단한 대상 | 철판, 금속 용기, 돌 계열, 유리 | 짧은 재질 잔향 |
| 플레이어 피격 | 몸 충격, 천, 가죽 | 하강 피드백 또는 날카로운 스침 |
| 기갑기마 착지 | 지면, 갑주, 가죽 | 지연된 장비 흔들림 |
| 불길 | 불꽃 소스, 천 스침 | 바람·입자·시간 변화 |
| 쇠뇌 장전 | 걸쇠, 목재 장력, 가죽 | 반복 동작과 잠금 시점 |
| 쇠뇌 발사 | 목재/금속 해제 | 현 모델과 빠른 공기 스침 |

이번에는 현업의 소재 선택·편집·레이어·정리 절차를 코드로 적용했다. 새 Foley 녹음이나 DAW 수동 편집을 했다고 주장하지 않는다. 원본 소재는 [Kenney RPG Audio](https://kenney.nl/assets/rpg-audio), [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds), [AntumDeluge Fire Crackling](https://opengameart.org/content/fire-crackling/)이다. 해당 제작자 페이지에서 CC0 표기를 확인하고 원본 라이선스/출처를 보존했다.

## 64개 후보의 의미

각 역할의 8개는 서로 다른 디자인 방향을 찾는 시안이다. 랜덤 재생용 8개 변형을 확정한 것이 아니다.
사용자가 고른 방향을 기준으로 다음 단계에서 작은 변형 2–3개, 게임 연결, BGM과 동시 재생 확인, 재생 수 제한을 검증한다.
파일 신호 검사와 브라우저 재생 검사는 수행했지만 실제 게임에서의 인간 청취/반복 피로 검증은 아직 수행하지 않았다.
