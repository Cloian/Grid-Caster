# 독립 여왕 보스 플레이테스트

사용자 요청: 보스전만 바로 체험하는 별도 Unity 씬. `Assets/Scenes/QueenBossPlaytest.unity`를 열어 Play, 왼쪽 `설정으로 시작`을 누른다. Editor 메뉴 `Tools → Playtest → Open Queen Boss Playtest`로도 열 수 있다. 정식 10·20웨이브의 구성과 Build Settings에는 연결하지 않았다.

## 실험 범위

보스 규칙은 Core, 바로 진입하는 테스트 씬·조건 선택은 Supporting이다. 목적은 강한 후반 빌드에서 이동·공격 순서와 반격 기회가 판단을 만드는지 확인하는 것이다. 플레이어는 기존 네 특성, 세 이동술과 실제 공격·점유·충돌 판정을 사용한다. 보스·근위병은 단색 그레이박스다. 최종 아트나 사운드로 난도를 평가하지 않는다.

새 시스템을 추가하는 대신 기존 `MoveCompleted → MonsterSpawner → QueenBossPlaytest` 턴 완료 흐름을 사용했다. `Update`는 키 입력, 연출, HUD 갱신만 처리한다. 입력이 없거나 방향을 선택·취소하는 동안 보스는 행동하지 않는다.

| 패턴 | 규칙 | 반격 기회 |
|---|---|---|
| 왕권 사격 | 직선/대각선 3줄을 교대로 예고. 두 번째 행동 뒤 피해 3 | 다음 1행동 |
| 왕실 포격 | 현재 위치 중심 3×3를 고정 예고. 2페이즈는 추가 구역. 두 번째 행동 뒤 피해 4 | 다음 1행동 |
| 근위대 전진 | 최대 세 명, HP 4. 아래로 한 칸 전진하거나 정면 플레이어에게 피해 1 | 다음 1행동 동안 정지 |
| 성벽 봉쇄·사격 | 2페이즈. 빈 칸 두 곳에 성벽. 이동·이동술 경로·탄을 차단하고 사격 예고 | 다음 1행동, 이후 성벽 소멸 |
| 체크메이트 | 2페이즈에서 일반 패턴 세 번 사이에 삽입. 예고 뒤 2행동째 A, 다음 행동 B. 안전구역 밖 피해 8 | 이후 2행동 |

1페이즈는 사격·포격·근위대 순환, HP 50% 이하는 성벽과 체크메이트가 추가된다. HP에 따른 처형이나 즉사는 확정하지 않았으므로 구현하지 않았다. 방어/보호 규칙은 기존 플레이어 피해 함수를 따른다.

체크메이트는 A/B 각 8칸을 함께 공개하고 서로 겹치지 않는다. 다음 A는 직전 B와도 겹치지 않는다. 현재 점유와 선택한 실제 이동술을 사용해 2행동으로 A, 1행동으로 B, B에서 여왕에게 사격 가능한 경로가 있는 후보를 고른다. 예고 후 구역을 바꾸지 않고 근위병도 정지한다. 해법이 없는 현재 배치에서는 일반 패턴을 한 번 더 쓰고 다시 검사한다. 이 조건이 궁극기 빈도를 지나치게 낮추는지는 플레이테스트에서 확인해야 한다. 시드는 Inspector에서 변경할 수 있고 같은 조건 재시작은 재현 가능한 시드를 사용한다.

여왕은 위쪽의 3×3칸을 점유한다. 직접 공격은 첫 몸 칸에 맞고, 관통은 같은 여왕에게 중복 적중하지 않는다. 범위 피해는 몸 일부가 범위에 들어오면 한 번 적용한다. 여왕은 밀리지 않지만 근위병을 여왕에게 밀어 충돌 피해를 줄 수 있다. 이동술이 막힌 성벽 경로를 통과하는 예고도 차단한다.

## 조건과 조작

- 네 특성: 더블 캐스트 / 관통 / 범위 공격 / 넉백.
- 이동술: 없음 / 나이트 / 비숍 / 룩, 1~3단계.
- 기본 빌드: HP 18, 기본 피해 2, 전용 강화 각 1중첩.
- 강한 빌드: HP 24, 기본 피해 3, 전용 강화 상한 내 2중첩과 특성 완성. 유물은 포함하지 않는다.
- 특성 공격을 준비한 상태로 시작한다. 전투 중에는 실제 일반 적중으로 충전한다.
- 1페이즈 HP 60부터 또는 2페이즈 HP 30부터 시작.
- A 일반 공격, F 준비된 특성 공격, S 이동/이동술, 클릭 확정, 우클릭 취소, Space 대기.
- ESC 일시정지. 효과음 ±10% 조절은 기존 `GameAudio` 설정에 저장한다. 사망·클리어 후 ESC를 닫아도 전투 입력을 다시 열지 않는다.
- 조건은 왼쪽 버튼으로 순환하고 `설정으로 시작`으로 적용. `같은 조건으로 다시`는 현재 전투 조건을 사용한다. 진행 중인 연출에서는 재시작을 제한하고, ESC로 멈춘 상태에서는 재시작할 수 있다.

## 확인할 판단과 위험

반복 플레이에서는 안전칸에 머무르며 공격만 하는지, 특성을 저장해 근위대를 정리하는지, A로 들어가기 전 두 행동을 어떻게 쓰는지, B에서 반격하기 위한 사격선을 고르는지 관찰한다. 빠른 반응을 요구하는 실시간 제한은 없다. 강한 빌드는 궁극기를 보기 전에 처치할 수 있으며 이를 막는 강제 무적이나 실시간 능력치 보정은 없다.

현재 프리셋은 후반 모든 유물 조합을 재현하는 것이 아니며, 고정 패턴 순환·피해·HP는 첫 비교용 수치다. 단순한 대안은 세 일반 패턴과 체크메이트만으로 먼저 평가하는 것이다. 성벽이 이동 선택만 복잡하게 하거나 넉백 빌드의 이점이 부족하면 패턴·배치부터 조정한다. 보스는 하단에서 사격하는 빌드와 근위대 충돌을 사용하는 빌드의 실제 완료 행동 수를 비교한 뒤 정식 런에 연결한다.

## 기술 및 검증

Unity 6000.4.0f1, 기존 URP 2D·Input System·uGUI를 확인했다. 새 패키지는 추가하지 않았다. 내부 13×13, 32 PPU Point의 단색 스프라이트, 기존 `PcBoardLayout` 카메라·HUD 배율을 사용한다. HUD는 고정 크기 Galmuri TMP 글리프를 정적 1024 atlas에 구워 런타임 한글 증설을 피했다. TMP 기본 리소스는 기존 uGUI 패키지에서 가져왔다.

`Tools → Playtest → Validate Queen Boss Playtest`는 실제 특성 공격 36구성, 실제 A→B 회피 경로 8구성, 입력 정지·관통·범위·성벽·승리·사망·재시작·UI raycast를 검사한다. 보고서: `docs/verification/queen-boss-playtest-2026-10-12.txt`. 제어된 픽스처 검증을 인간 플레이의 재미·밸런스 검증으로 해석하지 않는다.

2026-10-12 실행 결과: 보스 검사 341항목 PASS. 기존 `Validate Tactical Core`도 PASS, 별도 사본은 `docs/verification/queen-boss-tactical-regression-2026-10-12.txt`다. 기존 검증 도구는 최신 결과를 `tactical-core-2026-10-01.txt`에도 기록한다. 첫 보스 검사의 일시정지 버튼 테스트는 화면 갱신 전에 클릭한 픽스처 문제였고, 프레임 갱신 뒤 실제 raycast로 확인해 수정했다. 초기 실패 보고서도 보존했다.

Game View에서도 실제 클릭·키 입력으로 시작 → 사격 → 포격 → 근위대 → 체크메이트 공개를 확인했다. 예고 배경보다 플레이어를 앞에 그리고, 플레이어·근위병 칸에는 A/B 글자를 중첩하지 않는다. 자동 판정 검증 뒤 이 표시만 보완했다.

표시 보완 뒤 네이티브 입력 재확인: 강한 더블 캐스트·룩 3단계·2페이즈로 시작해 행동 9에 체크메이트를 공개했다. `(6,4)`에 이동 후 대기해 A를 회피하고, `(6,6)`으로 룩 이동술을 써 B를 회피했다. 행동 12에 플레이어 HP 17/24를 유지한 채 2행동 반격 기회가 열렸다. F·위 방향 클릭의 두 시전으로 여왕 HP 30→21, 행동 13, 특성 충전 0/2를 확인했다. ESC 패널을 열고 기본 빌드·1페이즈로 재시작해 여왕 60/60, 플레이어 18/18, 행동 0으로 되돌렸다. Unity는 이 첫 전투를 실행한 상태로 남겨두었다.
