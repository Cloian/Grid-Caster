# Grid-Caster 게임 정체성 — 최종 합의

## 상태와 문서 역할

2026-10-02 사용자의 최종 이해 승인으로 확정했다. `grill-with-docs` 정체성 인터뷰는 종료한다. 목표 경험과 개발 경계의 기준이며, 기능 구현 완료나 모든 후속 작업의 일괄 착수 승인을 뜻하지 않는다.

용어는 [CONTEXT.md](../../CONTEXT.md), 순서와 완료 조건은 [개발 워크플로우](development-workflow-2026-10-02.md)를 따른다. 기존 플랫폼·런 경계와 충돌하면 이 합의를 기준으로 정리하되, 최신 명시적 사용자 요청을 우선한다.

## 한 문장 정체성

**보드 전체를 읽고 전장의 기믹에 맞는 빌드를 구성한 뒤, 준비한 공격으로 위기를 해결하는 스테이지 완결형 턴제 전술 로그라이크.**

## 제작 의도와 핵심 재미

제작 의도는 기록된 발언에서 복원한다. 최초의 개인적 제작 계기까지 추측하지 않는다. 목표 감정은 **‘내가 판을 풀었다’와 ‘내가 고른 빌드가 제대로 터졌다’가 연결되는 것**이다.

- 중심: 전체 보드의 점유·적 규칙·공격선을 읽고 위치와 행동 순서를 선택하는 전술적 해결.
- 보조: 체스 말처럼 읽히는 보드의 존재감, 이동술과 준비한 특성 공격으로 여러 적을 처리하는 빌드 실현.
- 전술 60 / 빌드 30 / 성장 쾌감 10은 설계 지향이지 측정된 재미 비율이 아니다.
- 주요 타겟: 빠른 반응보다 배치·행동 순서·효과 조합을 고민하고, 실패를 이해하며 새 런에서 다른 해법을 시험하는 플레이어.

반복 구조는 **위협 읽기 → 유리한 배치와 공격 기회 준비 → 원하는 시점에 빌드 사용 → 결과 확인 → 다음 성장 선택**이다. 턴제나 체스 이동 패턴 자체가 사고의 깊이를 증명하지는 않는다.

## 플랫폼과 보드

PC를 주력으로 핵심 경험을 완성한다. 모바일 어댑터와 공개 링크는 보조 실험으로 보존하되, 휴대폰에 맞추려고 보드 판독성을 희생하지 않는다. 플랫폼과 배포 수단은 별개이므로 PC에서도 웹 링크 공유를 검토할 수 있다.

현재 첫 스테이지 기준은 **외벽 제외 내부 13×13, 8방향, 전체 보드 고정 시점**이다. 후속 맵 크기까지 영구 고정하지 않는다. 새 맵은 배경 교체나 단순 확대보다 같은 행동과 빌드 원리를 다르게 쓰게 하는 공간 조건을 제공해야 한다.

## 스테이지와 성장 경계

- 한 스테이지는 고정 맵에서 빌드를 쌓고 마지막 보스로 검증하는 하나의 독립 런이다. 목표 길이는 보스전 포함 약 30분이며 제한 시간·강제 대기·고정 웨이브 수를 뜻하지 않는다.
- 다음 스테이지는 새 맵·새 런·새 빌드로 시작한다. 런 내 능력과 보상을 이월하지 않으며 영구 능력치 성장은 도입하지 않는다.
- 사망하면 현재 스테이지 처음부터 새 빌드로 재도전한다. 이전 스테이지의 클리어 기록은 유지한다.
- 시작에는 핵심 특성 하나를 선택하고 성장 중 기존 강화·유물·이동술로 보조 효과를 조합한다. 두 번째 시작 선택이나 별도 성장 체계를 기본값으로 추가하지 않는다.
- 공통 선택지와 스테이지 전용 선택지를 함께 사용한다. 시작 후보도 스테이지별로 달라질 수 있다. 현재 네 공격 특성은 첫 스테이지 비교 기준이지 모든 스테이지의 영구 고정 목록이 아니다.
- 다른 특성의 전용 보상을 어디까지 조합할지는 후속 설계 대상이다. 조합 가능을 모든 핵심 특성·전용 부품의 무제한 동시 완성으로 해석하지 않는다.

## 확장 방향과 하지 않을 것

첫 스테이지의 판단·빌드 재미와 보스까지의 흐름을 먼저 검증한 뒤, 2·3스테이지에서 속성 특성을 소수씩 시험한다. 번개·얼음·화염·바람은 후보이며 지금 네 속성을 모두 제작한다는 합의가 아니다.

속성은 색·이름·피해 배율보다 적 배치·행동 순서·점유·이동 판단을 바꿔야 한다. 연결 표적 선택, 위협 지연, 예상 경로 활용, 변위·충돌은 가설이지 확정된 기술 목록이 아니다. 기존 봉쇄·넉백과 판단이 같다면 중복 시스템 대신 통합·대체를 검토한다.

자동전투·실시간 슈팅 전환, 완성 빌드 강제 지급, 제한 없는 모든 빌드 완성, 원소 반응·저항 체계의 임의 추가는 하지 않는다. 직업·동료·스토리 RPG로 범위를 확장하지 않는다.

## 강점·약점과 검증 기준

사용자는 이동술과 특성 공격을 조합한 연쇄 처치에서 만족감을 보고했다. 강점 후보는 공간 판단과 큰 공격 결과의 결합이다. 약점은 반복적인 안전 이동 → 공격 → 도주, 정보 판독성, 선택 효과와 결과의 불명확한 연결이다.

PC의 큰 화면이나 새 속성 자체가 재미 개선의 증거는 아니다. 규칙 일치는 자동 검사로, 왜 이동했는지·공격을 준비했는지·보상을 선택했는지·도주 외 해법이 생겼는지는 사람 플레이로 확인한다. 모바일 불편에 관한 사용자 피드백은 플랫폼 우선순위의 근거지만 모든 모바일 플레이어의 선호를 증명하지 않는다.

## 현재 구현과 목표의 차이

현재 코드 기준이며 이번 문서 확정으로 구현이 바뀌지는 않았다.

| 항목 | 현재 구현 | 남은 작업 |
|---|---|---|
| PC 화면 | 소스에서 데스크톱 Web/모바일 경로 분리, 보드/HUD 공통 배율 적용. 공개 링크는 이전 배포 유지 | [화면 검사](../verification/pc-screen-baseline-2026-10-02.md)와 별도로 사람의 전체 보드 판독성 확인 |
| 전투·성장 | 한 행동 후 적 턴, 수동 특성 공격, 이동술 하나, 공통·현재 특성 전용 보상 | 판단·조합의 재미 검증; 교차 전용 보상 경계 별도 설계 |
| 웨이브 | 번호별 고정 20웨이브, 10·20은 기존 몬스터 혼합전 | 고유 스테이지 보스·약 30분 흐름 |
| 클리어 | 20웨이브 종료 상태·입력/시간 차단·결과 패널·전장 복기·같은 씬 새 빌드 재시작 | 클리어 기록 저장·다음 독립 스테이지 전환 |
| 후속 스테이지 | 연결 및 새 맵 전환 없음 | 독립 런 전환·새 빌드·이전 기록 유지 |
| 속성 | 플레이어 원소 체계 없음; 비숍 불길은 적의 보드 위험 | 첫 스테이지 검증 후 제한된 속성 실험 |
| 중단·재개 | 공개 Web은 새로고침/탭 폐기 후 런 복원 안 됨 | 저장 범위·복원 규칙을 먼저 결정; 세부 구현 미확정 |

현재 일반 공격의 사거리 제한과 이동술의 별도 재사용 제한은 없다. 공간 보상은 있지만 도주 반복을 구조적으로 배제하지 않는다. 자동 검증은 규칙·회귀 자료이며 사람의 재미나 실제 30분 길이를 검증한 자료가 아니다.
