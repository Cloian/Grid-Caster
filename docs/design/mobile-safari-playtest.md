# Safari 모바일 플레이테스트

## 현재 우선순위

2026-10-02 [최종 정체성](game-identity-2026-10-02.md) 확정 후 PC를 주력으로 개발한다. 아래는 기존 모바일 어댑터·배포·검증 안내이며 보조 실험으로 유지한다. 현재 소스는 데스크톱 Web에 PC UI를, iPhone/Android/iPad 브라우저에 모바일 어댑터를 적용한다. PC 화면 정리와 검증 범위는 [별도 기록](../verification/pc-screen-baseline-2026-10-02.md)을 참고한다. 공개 링크는 이번 작업에서 갱신하지 않았다.

## 범위

사용자 선택: 네이티브 iOS 앱보다 Safari 링크 테스트를 먼저 진행한다. 기존 `SampleScene`, 13×13 플레이 보드, 8방향, 웨이브/성장/적 턴 규칙을 공유한다. 이번 작업은 입력·화면 어댑터이며 적 공격 시점·피해·밸런스를 변경하지 않는다.

모바일은 세로 전용 테스트다. 모바일의 가로·낮은 브라우저 화면에서는 세로 회전을 안내한다. 데스크톱 Web은 PC HUD와 A/S/F 조작을 유지하며 같은 크기의 작은 PC 창에는 회전 안내를 표시하지 않는다.

## 조작

1. 시작 특성과 시작 증강을 탭하여 선택한다.
2. 아래의 `이동`, `공격`, `특수공격` 중 하나를 선택한다.
3. 보드의 칸을 탭한다. 공격은 작은 화살표를 정확히 누를 필요 없이, 탭한 위치에서 가장 가까운 8방향으로 조준한다. 노란 경로는 기존 전투 미리보기 규칙을 사용한다. 이동은 표시된 실제 이동 가능 칸만 선택한다.
4. 같은 행동 버튼을 한 번 더 눌러 확정한다. 예: `이동` → 칸 탭 → `이동 실행`. 이동은 청록색 선택 칸과 반투명 플레이어로 실제 착지점을 표시한다. 공격은 `오른쪽 위`처럼 방향을 글로도 표시한다. 탭/취소/목록 확인 자체는 턴을 진행하지 않는다.
5. 보드 위쪽 `강화`, `유물`에서 목록과 상세 설명을 확인한다. 긴 목록/설명은 세로 스크롤한다. 목록을 닫은 터치는 뒤의 보드에 전달되지 않는다.
6. 행동을 고르지 않은 상태에서 특수 적을 탭하면 기존 조건부 위험 범위를 확인한다. 미래 AI 경로를 확정해서 보여주는 기능은 아니다.

추가 공격 방향 선택 중에는 이동과 취소를 허용하지 않는다. 왕의 무료 이동은 기본 한 칸 또는 `이동 생략`이며 이후 원래 적 턴이 진행된다. 특수공격은 일반 적중으로 준비되었을 때만 활성화한다.

보드 위쪽 `메뉴`에서 일시정지·재개·다시하기를 사용할 수 있다. 게임오버의 `전장 확인`으로 당시 보드를 복기하고 `메뉴`로 게임오버 창을 다시 표시한다.

## 보드 중심 화면

전투 중 하단에는 `이동 / 공격 / 특수공격` 한 줄만 상시 표시한다. 별도 실행 버튼은 제거하고 취소는 선택 중에만 표시한다. 웨이브/시간/체력/특수공격 준비도와 강화·유물·메뉴는 보드 위에 모아 배치한다. 모든 상시 UI와 취소 버튼은 보드 뷰포트 밖이며 13×13 플레이 칸과 경계 벽을 전부 유지한다. 모바일 카메라 여백만 줄이고 PC 카메라 여백은 유지한다.

정사각 보드의 크기는 세로 휴대폰의 가로 폭에 제한된다. 조작부를 줄였다고 타일이 두 배 커지는 것은 아니다. 높이가 좁은 인앱 브라우저에서도 필요한 상·하단 영역을 확보하고, 너무 낮은 화면에서는 보드 크기가 함께 줄어든다. 카카오톡 인앱 브라우저의 주소·탐색 막대는 게임이 제거할 수 없다.

## 빌드와 접속

### 인터넷 공개 플레이

공개 주소: **https://cloian.github.io/Grid-Caster/**

아이폰 Safari에서 세로 화면으로 열고 `터치하여 시작`을 누른다. 설치·로그인·같은 Wi-Fi·Mac의 실행 서버가 필요 없다. 카카오톡에서는 링크를 복사해 Safari로 연다. Safari 공유 메뉴의 `홈 화면에 추가`(표시되는 경우 `웹 앱으로 열기` 활성화) 후 홈 화면 아이콘으로 열면 브라우저 도구 막대를 제외한 웹 앱 화면을 사용할 수 있다. [Apple 공식 안내](https://support.apple.com/guide/iphone/iphea86e5236/ios)를 따른다. 이것은 웹 플레이 링크이며 App Store/TestFlight 설치 링크가 아니다. 인터넷 접속은 필요하고 새로고침 또는 탭 폐기 후 진행 중인 런은 복원되지 않는다.

GitHub Pages가 기존 공개 저장소 `Cloian/Grid-Caster`의 배포 전용 `gh-pages` 브랜치를 제공한다. 해당 브랜치는 Unity 실행 파일·manifest·시작 HTML·`.nojekyll`만 포함하며 개발 코드/씬/검증 로그를 게시하지 않는다. 개발 브랜치나 `main`으로 병합하지 않는다. [최초 배포 기록](../verification/public-web-2026-10-02.md)과 [보드 중심 UI 갱신 검증](../verification/mobile-board-ui-2026-10-02.md)을 확인한다.

### 같은 Wi-Fi의 로컬 테스트

Unity 6000.4.0f1의 **Web Build Support**가 필요하다. 새 UPM 패키지는 필요하지 않다. Mac의 Unity CLI 설치 오류는 beta.9 → beta.12 업데이트 후 공식 Web 모듈을 다시 설치하여 해결했다. iOS 모듈·Xcode·스토어 설정은 설치/변경하지 않았다.

현재 씬을 저장하고 Play를 종료한 뒤 Unity 메뉴 `Tools > Build > Mobile Safari Playtest`를 실행한다. 결과는 `Builds/MobileWeb`이다. `Assets/Editor/MobileWebBuild.cs`는 저장 씬·전역 PlayerSettings를 바꾸지 않고 Web 대상으로 빌드하며 실행 HTML/manifest를 생성한다.

```sh
node Tools/mobile-playtest/serve.mjs Builds/MobileWeb <Mac의 Wi-Fi IPv4> 8765
```

시스템 Node가 없다면 Codex 제공 Node 경로를 사용할 수 있다. 서버는 빌드 폴더만 공유하며 프로젝트 소스/상위 경로·외부 심볼릭 링크를 제공하지 않는다. Brotli/gzip 빌드 파일을 압축 없는 URL로 받아 서버에서 해제하므로 같은 Wi-Fi의 HTTP 접속에서도 작동하도록 구성했다. 이 테스트 manifest는 제공 서버의 압축 URL 별칭을 전제로 하므로 다른 호스팅에 올릴 때는 서버 설정을 다시 검증해야 한다.

아이폰과 Mac을 같은 Wi-Fi에 연결하고 출력된 주소를 **Safari**에서 연다. Mac과 서버가 켜져 있어야 한다. 이것은 인터넷 공개 주소나 TestFlight 설치 링크가 아니다. 네트워크의 기기 간 통신 차단·Mac 방화벽·VPN은 접속을 방해할 수 있다. 공유망/공용 Wi-Fi보다 신뢰하는 개인 Wi-Fi를 사용한다.

### 다음 공개 빌드 포장

```sh
node Tools/mobile-playtest/package-static.mjs Builds/MobileWeb /absolute/path/to/empty-output
```

이 스크립트는 재빌드나 Unity 설정 변경 없이 검증된 Web 결과물을 정적 호스팅용으로 포장한다. 출력 폴더가 비어 있지 않으면 거부한다. Brotli/gzip 파일을 원래 바이트로 복구하고 내용 해시 경로로 manifest를 변경하여 Pages의 응답 헤더 제약과 업데이트 중 캐시 혼합을 피한다. Pages는 이를 다시 gzip 전송한다. StreamingAssets가 새로 생기면 검토 없이 공개하지 않도록 실패한다. 결과물 전체를 개발 브랜치에 추가하지 말고 배포 전용 브랜치에서만 갱신한다.

## 연결/Inspector

새 GameObject를 만들거나 Inspector 필드를 수동 할당할 필요가 없다. 기존 GameHUD의 `GameHudController.Start`가 모바일 기기/모바일 브라우저 실행에서만 `MobilePlaytestController`를 자동 연결한다. Web의 기기 판별은 `Assets/Plugins/WebGL/GridCasterBrowser.jslib`를 사용한다. 기존 Canvas/EventSystem/Input System·플레이어·GridManager·성장 UI를 재사용한다. 새 태그·레이어·Tilemap·Collider·Sprite·몬스터 Prefab을 추가하지 않았다. 스프라이트의 32 PPU/Point 설정은 변경하지 않는다.

모바일 Canvas 기준은 390×844, 가로 기준 배율이다. 카메라에는 고정 정사각 보드 뷰포트를 사용하고 그 위/아래로 HUD와 버튼을 배치한다. 웹 HTML은 기기 안전 영역과 터치 브라우저 스크롤을 처리한다. 긴 상세창과 강화/유물 목록은 Mask가 있는 ScrollRect를 사용한다. 전투 로직은 `Move.ConfirmPreviewCell`에서 기존 이동/공격 판정을 재사용한다.

## 아직 포함하지 않은 것

- 네이티브 iOS 앱, App Store/TestFlight.
- 브라우저 재시작/새로고침 후 런 이어하기. 이번 플레이는 초기화된다. 최고 기록의 기존 저장 동작은 별개다.
- 모든 iPhone의 Safari 메모리·발열·프레임 성능 보장, 가로 모드 UI.
- 적 위협도/피해 조정. 별도 요청에서 동일한 적 턴 규칙을 지키며 검토한다.

앱 전환/탭 숨김은 일시정지를 요청하고 돌아왔을 때 자동으로 적 턴을 진행하지 않는다. 다만 iOS가 브라우저 탭을 메모리에서 제거하면 상태를 복구하지 못한다. 실제 아이폰에서 이 동작과 터치 감각을 확인해야 한다.
