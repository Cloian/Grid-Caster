# 퀸 후보 v4 — 디자인 검토

## 결과와 추천

세 후보는 승인된 폰 근위대를 수정하지 않고 별도로 제작했다. create-game-assets의 아트 디렉션·가족 일관성·배경 비교·기술 검수 절차를 적용했고, 생성은 내장 image_gen으로 수행했다.

| 후보 | 확인한 형태 | 장점 | 남은 문제 |
|---|---|---|---|
| A 가면 여왕 | 큰 가면과 삼각 망토 | 근위대와 같은 왕실 진영이 쉽게 읽힘 | 차갑고 두개골 같은 가면 인상이 남으며 기존 퀸과 차이가 작음 |
| B 날개 여왕 | 넓은 날개와 짧은 몸 | 넓은 실루엣과 대각선이 뚜렷하며 동물형 보스 개성이 강함 | 나방을 의도했으나 현재 결과는 올빼미 인상도 강함. 보드의 주변 정보가 가려질 수 있음 |
| C 왕좌 여왕 | 작은 여왕과 각진 부유 왕좌 | 얼굴·왕관·몸의 구분이 좋고 근위대와 왕실 관계가 자연스러움 | 왕좌 때문에 고정형으로 오해될 수 있음. 추후 이동 연출에서 부유·이동 여부를 설명해야 함 |

현재 디자인 추천은 **C 왕좌 여왕**이다. 역할·가독성·승인 근위대와의 일관성을 기준으로 한 판단이며 사용자의 취향 승인이나 재미 검증을 대신하지 않는다. 동물형 정체성을 우선할 경우 B가 더 큰 형태 차이를 제공한다.

## 검토 이미지

- comparison.png: 동일 크기 확대·120px 화면 표시·캔버스 높이 약 2칸 가상 보드 배치.
- comparison-120px-at-32ppu.png: 120px를 32 PPU로 환산한 3.75유닛 캔버스 가상 배치.
- comparison.html: 두 크기를 전환하는 로컬 비교판.

CSS와 브라우저로 원본 PNG를 표시하고 저장된 게임 화면에 겹쳐 비교했다. 이미지 생성 원본은 수정하지 않았다. 썸네일은 렌더링 크기 비교이며, 120×120 실제 도트 원본을 제작한 것으로 취급하지 않는다. 보드 화면은 가상 배치이고 Unity 플레이 검증이나 점유·충돌 규칙 구현 화면이 아니다. 캔버스 크기와 본체 실루엣 크기도 다르다.

## 기술 검수

asset_report.py로 각 파일을 기대 크기 120×120, 알파 채널 필수, 최대 12색 조건에서 검사했다. **세 파일 모두 최종 에셋 규격 검수 실패**다. 실제 생성 크기는 1254×1254이며 색상 수가 12색을 초과한다. 투명 배경은 있지만 반투명 가장자리와 큰 출력에 남은 색상 변화를 별도 정리해야 한다. 정확한 보고서는 qa-report.json에 보존한다.

선택한 후보의 최종 도트 제작은 120×120 격자에서의 재설계·11~12색 제한·알파 0/255·윤곽과 클러스터 검수 후 진행한다. 단순히 큰 이미지를 축소해서 규격 통과로 처리하지 않는다.

## 원본과 프롬프트

- PNG 3개는 image_gen 출력 복사본이다. 생성 원본은 보존했다.
- asset-manifest.json에 실제 프롬프트와 참고 이미지 및 생성 원본 경로를 기록했다.
- C는 차가운 돌가면이 반복되는 것을 줄이기 위해 폰 이미지 참조를 제외하고 팔레트를 텍스트로 유지했다. 실제 호출의 프롬프트와 참고 이미지 목록을 manifest에 기록했다.
- brief.md는 생성 전 계획 기록이다. B의 종족 인상과 C의 최종 프롬프트 차이는 이 검토 기록 및 manifest를 따른다.
- 기존 근위대, 이전 퀸 시안, Unity Assets·씬·게임 규칙·공개 배포는 이번 작업에서 수정하지 않았다.
